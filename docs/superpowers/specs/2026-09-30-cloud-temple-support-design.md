# Cloud Temple Provider Support Design

Date: 2026-09-30

## Goal

Add [Cloud Temple](https://docs.cloud-temple.com/en/llmaas/api) as an opencode
model provider, with a manually curated sub-agent -> model mapping, and a
script that turns [modelgrep](https://modelgrep.com/api) ratings into a
data-backed proposal for that mapping.

- A harness part contributes Cloud Temple as an OpenAI-compatible provider.
- A second part maps agents (`build`, `plan`, `general`, `semble-search`) to
  specific Cloud Temple models. Manually curated, not generated.
- A lib function enriches any harness with both parts, exposed as
  `<harness-name>-llmaas`. Wired up for `vanilla-dev` and `superpowers`.
- A script fetches/caches Cloud Temple's model list and (re)generates the Nix
  model catalog from it.
- A script fetches/caches modelgrep ratings, matches them against Cloud
  Temple's models (best-effort, structural), and prints unmatched models,
  per-model metrics, and a coding-focused mapping proposal.
- Both scripts default to cached data in `data/`; fetching/regenerating are
  explicit opt-in flags.

## Decisions

### Provider config

`config.opencode.provider.cloud-temple`, `@ai-sdk/openai-compatible` npm
package (confirmed via opencode docs: use this SDK for `/v1/chat/completions`-
style endpoints), `options.baseURL = "https://api.ai.cloud-temple.com/v1"`,
`options.apiKey = "{env:CLOUD_TEMPLE_API_TOKEN}"`. `models` comes from the
generated catalog (below).

### Generated vs. constant split

- `harnesses/parts/generated/cloud-temple-models.nix` — **generated**, 1:1
  transform of `data/cloudtemple-models.json` (`{ "<id>" = { name = "<id>"; };
  }` for every model, no filtering). Regenerated by
  `fetch-cloudtemple-models.py --update`, not hand-edited.
- `harnesses/parts/cloud-temple.nix` — **constant**, hand-authored provider
  metadata (npm, name, baseURL, apiKey env var), imports the generated file
  for `models`.
- `harnesses/parts/cloud-temple-agents.nix` — **constant**, hand-curated
  `config.opencode.agent.<name>.model = "cloud-temple/<id>"` entries for
  `build`, `plan`, `general`, `semble-search`.

No generator/check pipeline (unlike `lib/types/generated.nix`): this data
comes from a committed file already, not a live fetch at check-time. Light
split is sufficient.

### Enrichment function

`lib/mkHarness.nix` gains `enrichWithLLMaaS`, exported from `lib/default.nix`
alongside `mkHarness`:

```nix
enrichWithLLMaaS =
  { name, modules, wrapArgs ? null }:
  mkHarness {
    name = "${name}-llmaas";
    modules = modules ++ [
      (import ../harnesses/parts/cloud-temple.nix { })
      (import ../harnesses/parts/cloud-temple-agents.nix { })
    ];
    wrapArgs = (if wrapArgs == null then defaultWrapArgs else wrapArgs) + " -e CLOUD_TEMPLE_API_TOKEN";
  };
```

Each harness file builds its `modules` list once (as today), calls
`mkHarness` for the plain package, and calls `enrichWithLLMaaS` with the same
`modules` for the `-llmaas` sibling; both are returned from the harness file
(`llmaas.package`, `llmaas.devShell`). `flake.nix` wires
`packages.<name>-llmaas`, `devShells.<name>-llmaas`,
`checks.<name>-llmaas` for `vanilla-dev` and `superpowers`.

Threading `-e CLOUD_TEMPLE_API_TOKEN` into `wrapArgs` here (not in
`cloud-temple.nix`) matches `creating-harness-parts`: parts contribute
`config`, not jail args; jailing env vars for runtime secrets is the
harness/enrichment's job.

### Script 1 — `scripts/fetch-cloudtemple-models.py`

```
fetch-cloudtemple-models.py [--fetch] [--update]
```

- `--fetch`: `GET {baseURL}/v1/models` with `Authorization: Bearer
  $CLOUD_TEMPLE_API_TOKEN`, overwrite `data/cloudtemple-models.json`.
- `--update`: regenerate `harnesses/parts/generated/cloud-temple-models.nix`
  from the current `data/cloudtemple-models.json` (piped through `nixfmt`,
  same convention as `generate-types.py`).
- No flags: no-op; prints cached model count and a reminder of both flags.
- Flags are independent and composable (`--fetch --update` refreshes both in
  one run).
- Exposed as flake app `update-cloudtemple-models`.

### Script 2 — `scripts/cloudtemple-model-report.py`

```
cloudtemple-model-report.py [--fetch]
```

- `--fetch`: fetch the full modelgrep catalog (`GET /v1/models`, paginated,
  no auth) and overwrite `data/modelgrep-models.json`.
- No flag: use cached `data/modelgrep-models.json` (must exist).
- Reads `data/cloudtemple-models.json` (must exist — run script 1 first).
- Exposed as flake app `cloudtemple-model-report`.

**Matching** (best-effort, structural — provider + name + weight class must
all agree):

1. Parse each Cloud Temple `id`/`root` into `(org, family, quant_suffix)`:
   `Org/Repo[-quant]` form (e.g. `Qwen/Qwen3.8-27B-FP8`) or bare `family:size`
   form (e.g. `gemma4:31b`).
2. Resolve `org` for bare-tag ids via a small family-prefix -> maker lookup
   table (`gemma`->`google`, `llama`->`meta-llama`, `qwen`->`qwen`,
   `granite`->`ibm`, `mistral`/`ministral`/`devstral`/`voxtral`->`mistralai`,
   `gpt-oss`->`openai`, `nemotron`->`nvidia`, ...). Unresolvable prefixes fall
   through to "unmatched".
3. Parse the param count out of the id (`31b` -> 31, `567m` -> 0.567,
   `27B` -> 27).
4. Candidate match in modelgrep data requires: `org` == modelgrep `maker`
   (case-insensitive) or matches the `hugging_face_id` org segment, **and**
   normalized base-name tokens overlap after stripping
   quant/instruct/version suffixes, **and** `open_weights.params_b` within
   15% of the parsed param count. All three required; first candidate
   passing all three wins.
5. Everything else -> unmatched (expected for embedding/rerank/TTS/vision
   models like `bge-m3`, `kokoro`, `pico2wav` — modelgrep is an LLM ratings
   site, not a full model registry).

**Output:**

- Unmatched Cloud Temple models (id list).
- Per matched model: `performance` (throughput/latency), `capabilities`,
  `benchmarks.artificial_analysis.{coding,intelligence}`,
  `benchmarks.design_arena.elo`.
- Proposed mapping for `build`, `plan`, `general`, `semble-search`: rank
  matched models with `capabilities.tools == true` by
  `benchmarks.artificial_analysis.coding` (fallback `.intelligence` when
  coding is null), print top candidate per agent slot with its metrics.
  Coding-focused since that's this repo's primary use.

`cloud-temple-agents.nix` is **not** auto-written from this script's output —
it stays hand-curated. `semble-search`'s entry is a best-guess placeholder
until this script has run once against real modelgrep data.

## Repo layout

```
data/cloudtemple-models.json                       # cache, script 1
data/modelgrep-models.json                          # cache, script 2 (new)
harnesses/parts/generated/cloud-temple-models.nix   # GENERATED by script 1 --update
harnesses/parts/cloud-temple.nix                    # constant: provider metadata
harnesses/parts/cloud-temple-agents.nix             # constant: curated agent->model map
lib/mkHarness.nix                                   # + enrichWithLLMaaS
scripts/fetch-cloudtemple-models.py                 # new
scripts/cloudtemple-model-report.py                 # new
```

`flake.nix`: `apps.update-cloudtemple-models`,
`apps.cloudtemple-model-report`; `packages`/`devShells`/`checks` for
`vanilla-dev-llmaas` and `superpowers-llmaas`.

## Testing

`checks.vanilla-dev-llmaas` / `checks.superpowers-llmaas` (jq-asserted per
`creating-harness-parts`): `provider.cloud-temple.npm ==
"@ai-sdk/openai-compatible"`, `.options.baseURL`, `agent.build.model ==
"cloud-temple/<id>"` etc. via `debug config`. Scripts are advisory/networked —
no flake check, verified manually.

## Open questions (resolved)

- Mapping scope: **primary agents (`build`/`plan`/`general`) + custom
  subagents (`semble-search`)**, not subagents only.
- Generated/constant split weight: **light** — two `.nix` files, no
  generator+check pipeline.
- `-llmaas` wire-up scope: **both** `vanilla-dev` and `superpowers`.
- Script 1 default behavior: **`--fetch`/`--update` as independent explicit
  flags**, not implicit/automatic.
- `semble-search` mapping value pre-script-2-run: **best-guess placeholder**,
  revisit after first real report run.
